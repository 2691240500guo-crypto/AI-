三、评审发现：亮点

① 双知识源分层融合
Milvus 管「模糊知识」（文档片段），Neo4j 管「确定规则」（宜忌三元组），prompt 层融合且明确「图谱结论优先」——比单一 RAG 更适合健康场景的严肃性要求。
② 有界状态机
LangGraph 采用「先规划后执行」（进图前路由、最多 4 步、一条直线），规避了 Agent 无限循环/失控调用，可控可测。
③ 能力边界诚实
舌象 14 类特征带可信度分档（high/medium/low/unusable），不可信特征不进结论只进明细——这是 AI 产品里难得的自我声明机制。
④ 禁忌规则即代码即数据
图谱从代码常量 MERGE 幂等灌入，「加一条禁忌边即生效」，且 (食物)-[:含有]->(营养素)-[降低风险]->(疾病) 两跳自动推理，扩展成本低。

四、评审发现：风险与待改进项

编号问题等级建议
R-01舌象「暗红（紫舌）」类召回为 0，产品已声明不可用并排除出结论，但数据集侧无短期修复路径中维持现状 + 前端角标；长期等 TongueDx 的 Purple 标注或临床样本
R-02意图路由是关键词表（ROUTE_KEYWORDS），复杂表达可能漏路由（如"晚上总醒"不含"睡眠"）中答辩可讲成「低成本高可控」；后续可加 LLM 兜底路由（一次低成本分类调用）
R-03图谱数据为人工预置常量（约 40 食物/20 营养素/15 疾病），覆盖面有限，与知识库文档不互通中已有 build_graph_from_llm.py 扩谱脚本；答辩口径为「人工审核保证严肃性，工具支持扩展」
R-04多 Agent 顺序执行，跨域问题耗时随 Agent 数线性增长（每个 Agent 一次 LLM 调用）中前端已有步骤回放缓解等待感知；可考虑并行无依赖 Agent（需评估 handoff 语义）
R-05周报/月报 Redis 缓存 120s，演示时刚记录的数据可能不立即反映低演示前预热数据；或记录成功后主动失效对应缓存键
R-06社区文本机审是本地红线词库（非 LLM），变体绕过能力弱低图片已走视觉机审；文本可后续升级为 LLM 审核，当前够用
R-07NRS2002 评分是规则引擎非 LLM——答辩话术若说成"AI 打分"属于事实错误低统一口径：规则引擎评分（可解释、可复现），LLM 仅做报告增强

五、评审结论

结论：通过（有条件）。 12 个业务域中 10 个已实现且经测试验证（pytest 11 passed、vite build 通过、端到端接口实测覆盖），核心链路（测评/问答/计划/图谱）具备答辩演示条件。条件项：① 演示前按 R-05 预热周报数据；② 话术统一 R-07 的技术边界；③ 舌象演示避开「暗红」特征或主动讲解能力边界（本身即是加分项）。
