## 3. 两版训练对比（都在同一份去重后的 14 类数据上）

| | v1（默认增强） | v2（舌象专用增强） |
|---|---|---|
| 增强参数 | mosaic 1.0 / erasing 0.4 / scale 0.5 / fliplr 0.5 / hsv_s 0.7 / cls 0.5 | **mosaic 0 / erasing 0 / scale 0.25 / fliplr 0 / hsv_s 0.3 / cls 1.0** |
| epochs | 100（跑满） | 150 设定，**127 触发早停**（best 在第 27 轮） |
| mAP50 / mAP50-95 | 0.388 / 0.299 | 0.385 / 0.297 |
| **图级 macro P / R / F1** | 0.474 / 0.464 / **0.413** | 0.465 / **0.500** / **0.420** |
| 标签集合完全一致 | 22.1% | **22.8%** |

**结论：mAP 口径基本没有变化；产品口径（图级）v2 略优。**

### 必须说清的一件事：我上一轮的判断只对了一半

上一轮我把 mAP 偏低归因于"增强参数不对"，并预期 v2 能把 mAP 提到 0.5 以上。**实测没有实现**
（0.388 → 0.385）。所以"增强参数是主因"这个判断是**错的**。

但换到产品口径后，v2 的进步是真实的，而且集中在你最关心的两类：

| 特征 | v1 图级 R | v2 图级 R | 变化 |
|---|---|---|---|
| 黄苔 | 0.551 | **0.735** | **+18.4pp** |
| 红舌 | 0.313 | **0.558** | **+24.5pp** |
| 裂纹舌 | 0.439 | **0.701** | **+26.2pp** |
| 白苔 | 0.990 | 0.972 | -1.8pp |
| 紫舌（暗红） | 0.278 | **0.000** | **-27.8pp ⚠️** |

**为什么关掉 mosaic 会让紫舌归零**：mosaic 把 4 张图拼成 1 张，等于让稀有类在一轮里被"多看到几次"。
紫舌全库仅 244 个实例，关掉 mosaic 后它的有效曝光量骤降。这是**稀有类与整体指标的取舍**。

**选型决定：线上用 v2**。理由是产品要的核心是白苔/黄苔/红舌（v2 全部更优或持平），
紫舌两版都不可用（v1 也只有 5/18），不值得为它牺牲其余 3 类。

## 4. 为什么对外不用 mAP

mAP 衡量的是**框画得准不准**；本模块的用途是**判断舌象上出现了哪些特征**，框的精确位置不影响结论。
实测两种口径差异巨大：

```
整体 mAP50            = 0.385   ← 看着很差
其中「白苔」图级召回   = 0.972   ← 实际几乎不漏
```

原因是 TCM-Tongue 的标注混合了两种粒度：

- **整舌级标注**（白苔 / 黄苔 / 红舌 / 紫舌）→ 框几乎覆盖整个舌面
- **局部级标注**（裂纹 / 齿痕 / 红点 / 分区凹陷）→ 框很小，红点舌仅约 4×9 像素

把两种粒度塞进同一个检测头，整舌级类会因为"框画不满"被扣分，局部级类会因为"太小看不见"被扣分，
于是整体 mAP 被拉低——**但整舌级类的分类判断其实是准的**。

**所以对外表述只用图级指标**，复现命令：

```powershell
cd backend
./venv/Scripts/python.exe scripts/evaluate_tongue_features.py `
    --weights models/tongue/yolov8n-tcm-tongue-v1.pt models/tongue/yolov8n-tcm-tongue.pt --conf 0.25
# 报告 → backend/eval_out/tongue_imagelevel.{txt,json,csv}
```

## 5. 「暗红」能力缺失的完整证据链与归因

你流程图要求的舌色 3 类（淡红 / 红 / 暗红）里，**暗红目前给不了**。

### 5.1 先排除最容易误判的两个原因

**① 不是训练参数问题**

| | v1（默认增强） | v2（定制增强） |
|---|---|---|
| 紫舌测试集支持数 | 18 张 | 18 张 |
| 图级召回 | 0.278（5/18） | **0.000（0/18）** |
| 图级 F1 | 0.185 | 0.000 |

两套完全不同的增强参数都学不出来 → 参数不是变量。

**② 也不是阈值卡住了**

把紫舌判定阈值从 0.25 一路降到 0.05（模型确实在 6/18 张图上输出了紫舌，置信度 0.05~0.18）：

| 阈值 | 召回率 | 误报图数 | 精确率 |
|---|---|---|---|
| 0.05 | 0.333 | **37** | **0.140** |
| 0.10 | 0.111 | 19 | 0.095 |
| 0.15 | 0.056 | 11 | 0.083 |
| 0.25（线上） | 0.000 | 2 | 0.000 |

**没有任何阈值可用**——捞回 6 张真阳的代价是 37 张误报。健康产品里这是不可接受的。

### 5.2 真正的主因：类别竞争 + 视觉可分性差

**证据 1｜样本量不是决定因素（关键对照）**

| 类别 | train 图数 | test 支持数 | 图级召回 | 判读 |
|---|---|---|---|---|
| `shoushe` 瘦小舌 | **217** | 30 | **0.767** | 样本很少却测得准 |
| `zishe` 紫舌（暗红） | **200** | 18 | **0.000** | 支持数几乎相同，结果相反 |
| `hongdianshe` 红点舌 | **1034** | 80 | **0.050** | 样本全库第二多，照样测不到 |

→ 200 张训练图**足够**学会一个类（`shoushe` 就是证明）；反过来说 1034 张也可能学不会。
**支撑数不是决定变量**，类别本身的可学性才是。

**证据 2｜紫舌与红舌在标注上互斥、且数量悬殊 1:6**

| | 只有紫舌 | 只有红舌 | 两者同图 |
|---|---|---|---|
| train | 194 | 1208 | **6** |
| val | 22 | 115 | 3 |
| test | 18 | 147 | **0** |

舌色是同一个视觉维度上的**互斥选项**，两者几乎不同图出现。而红舌的图数是紫舌的 6 倍，
于是模型直接押注多数类：**18 张紫舌图里有 11 张被预测成「红舌」**（置信度最高到 0.72）。

**证据 3｜「暗红 vs 红」在图像统计上边界就模糊**

用整图颜色/亮度做规则判别（阈值在 train+val 上标定 → 在 test 上评估，避免拿测试集调参）：

| 特征 | 紫舌中位 | 红舌中位 | 测试集准确率 | 紫舌召回 | 紫舌精确率 |
|---|---|---|---|---|---|
| R 通道 | 141 | 152 | 0.690 | 0.833 | 0.500 |
| 亮度 V | 145 | 154 | 0.672 | 0.833 | 0.484 |

召回到 0.83 了（说明"暗"这个信号确实存在），**但精确率只有 0.5——判成紫舌的一半是错的**。
即：两类在图上的分布大面积重叠，用一个整图统计量分不开。

**证据 4｜一个被排除的假说（记录以免重复踩坑）**

最初怀疑"白苔覆盖舌面 → 看不到舌色"，因为 18 张紫舌图**全部**同时标了白苔。全库统计后**被排除**：

| 类别 | 图数 | 同时有白苔 | 占比 |
|---|---|---|---|
| 紫舌 | 243 | 141 | 58.0% |
| **红舌** | 1479 | 877 | **59.3%** |

红舌的白苔共现率与紫舌一样高 → 白苔不是紫舌特有的干扰。
（不过它确实有次要影响：紫舌在"有白苔"组出现率 2.95%，在"无白苔"组 6.36%，差 2 倍——
舌面被苔覆盖时标注者自己也更难判舌色。）

### 5.3 结论

> **主因是「与红舌的类别竞争（1:6）+ 视觉可分性低」，样本量只是放大因素，不是决定性因素。**
> 换句话说：**就算把紫舌样本补到和红舌一样多，也未必能训好**——因为"暗红 / 红"这条标注边界本身在图像上就模糊。

### 5.4 可行路径（按性价比排序）

| 方案 | 做法 | 预期 | 成本 |
|---|---|---|---|
| **A. 改任务形式（最根本）** | 舌色/苔色本质是**整舌级分类**，不该塞进检测头。用现有单类定位权重 `yolov8n-tongue.pt.bak` 取舌体 ROI → 再训一个 3 类分类头（淡红/红/暗红） | 同时能救红舌（现仅 0.56）与暗红；分类任务比检测简单得多 | 中等工作量，本地 CPU 可训 |
| **B. 降成二分类** | 不问"是哪种舌色"，只问"舌色是否偏暗" | 二分类所需样本量与可分性要求都低得多 | 小 |
| **C. 补样本** | 把紫舌补到 ≥500~1000 张，且**同一采集条件**（同一批设备/光源） | 效果不确定（见 5.3），但能改善 | 需标注资源 |
| **D. 合并类别** | 产品上把"红/暗红"合并为"舌色偏红偏暗"一档 | 立刻可用，但丢失用户要的区分度 | 零 |
| ❌ 降阈值 | — | 精确率 0.14，大量误报 | 不可取 |

**当前产品的处理方式**：不猜、不编。检测到紫舌时仍会展示（角标"不可用"），但**不写进结论**；
舌色结论若落到默认值，依据行会明确写「未检出明确舌色特征，按常见淡红处理（**暗红特征模型暂不可用**）」。

1. 补紫舌样本（找中医标注，或从 TongueDx 等数据集的 `Purple` 属性补充），再训一版；
2. 产品层面接受"舌色只给 红 / 淡红"，把暗红列入待办。

## 8. 决策记录

### 2026-09-11｜「暗红」不再继续投入，维持现状交付

**决策**：暂**不**实施第 7 节中的 A（改任务形式）/ B（降二分类）/ C（补样本）三条路径，
产品维持当前设计——**暗红不入结论**，其余特征照常输出。

**理由**（基于第 5 节实测证据）：

1. **投入产出比不成立**：A 方案需约 2 小时验证（含造标签、ROI 提取、训练、评估），若有效再 +1~1.5 小时接入；
   而第 5.2 节证据 3 显示「暗红 vs 红」在图像统计上分布大面积重叠（紫舌精确率仅 0.50），
   **换任务形式能改善召回但改不掉"标注边界模糊"这一根本困难**，精确率大概率仍不达标。
2. **影响面有限**：14 类特征中只有 `zishe`（暗红）、`huataishe`（滑苔）、`hongdianshe`（红点舌）3 类不可用，
   其余 11 类可用或可参考——**用户要的核心能力（白苔 0.972 / 黄苔 0.735 / 红舌 0.558 图级召回）已达标**。
3. **产品侧已有正确兜底**：`FEATURE_RELIABILITY` 可信度闸门已把不可用特征挡在结论之外，
   前端如实标注「不可用」并展示能力边界，**不存在"编一个数值"的合规风险**。

**后续若条件变化可重启该议题**：拿到临床标注的紫舌样本（≥500 张、同一采集条件），或 TongueDx 的 `Purple` 属性。
